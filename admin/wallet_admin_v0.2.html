1

문서 개요

1.1

목적

헥토월렛 1차 오픈에 필요한 어드민 범위와 화면별 동작을 하나의 문서로 정의한다. 1차 어드민의 핵심 목적은 다음과 같다.
  1. 회원의 가입·본인확인·지갑 생성 상태 조회
  2. 운영상 제한이 필요한 회원의 특정 서비스 기능 차단
  3. 검증된 코드 템플릿을 이용한 공식 스마트 컨트랙트 콘텐츠 생성
  4. 이용자가 만든 스마트 컨트랙트 조회와 서비스 노출 관리
  5. 우리 서비스가 생성하는 헥토코인 지급 요청의 조건부 관리
  6. 주요 변경 기능의 처리 이력 보관
개인키·시드 문구·MPC 키 조각과 사용자 자산은 어드민의 관리 대상이 아니다.
1.2

기준 문서 사용 원칙

문서 사이에 내용이 다른 경우 다음 우선순위를 적용한다.
  1. 본 프로젝트 논의를 통해 확정한 결정
  2. 본 통합 기능정의서
  3. 최신 헥토월렛 HTML 기능정의서
  4. SC DIY 플랫폼 기능정의서
  5. 온보딩·이전 월렛 앱 기능정의서
HTML과 SC DIY 엑셀은 이용자 화면·스마트 컨트랙트 동작 정의 문서다. 두 문서의 모든 기능을 어드민 요구사항으로 가져오지 않는다. 06_AM_운영자콘솔 시트는 목록·상세·노출·이력에 필요한 일부만 축소 참고한다.

2

확정 결정 요약

2.1

회원·본인확인

  • 본인확인 리워드는 CI 1개당 1계정에만 지급한다.
  • 어드민에는 CI·DI 원문을 표시하지 않는다.
  • 회원 화면에는 미인증 · 인증 완료 · 타 계정 인증 완료 수준의 상태만 표시한다.
  • 블랙리스트는 CI가 아닌 선택한 회원 계정 UID 단위로 적용한다.
2.2

지갑

  • 우리 서버에는 최소한 지갑 생성 상태를 저장할 수 있는 것으로 본다.
  • 지갑 주소는 네트워크별로 개별 생성되는 것으로 기획하되 개발·옥텟 확인이 필요하다.
  • 1차 지원 네트워크는 비트코인·이더리움·아비트럼·폴리곤·BNB·카이아 6개다.
  • 회원 목록에는 완료 네트워크 수/6 요약을, 회원 상세에는 네트워크별 생성 상태를 표시한다.
  • 지갑 고유번호·공개 주소를 서버가 보유하더라도 기본 마스킹한다. 전체 주소 열람·복사 정책은 데이터정책팀 확인 필요 전 확정하지 않는다.
2.3

화이트리스트

  • 목적은 사내·QA 테스트 계정 관리다.
  • 적용 시 실제 서비스에서 변경되는 동작은 아직 확정되지 않았다.
  • 메뉴는 정보구조에 유지하되 적용 정책 확정 전까지 개발 보류한다. 1차 완료 기준에 포함하지 않는다.
2.4

블랙리스트

  • 스마트 컨트랙트 신규 생성 · 신규 참여 · 헥토코인 신규 지급 요청 3개 기능을 개별 선택해 제한한다.
  • 등록 저장 즉시 제한을 적용한다. 종료일은 선택 입력이며 미입력 시 수동 해제 전까지 유지, 입력 시 해당 일자 종료와 함께 자동 만료한다.
  • 등록·수정·해제 사유는 모두 자유 입력 필수다. 모든 수정은 변경 전후 값과 처리 관리자를 이력으로 남긴다.
  • 지갑 받기·보내기, 기존 자산, 기존 컨트랙트 결과 조회·청구, 이미 전달된 지급 요청에는 소급 적용하지 않는다.
2.5

스마트 컨트랙트

  • 일반 이용자가 검증된 코드 템플릿으로 스마트 컨트랙트를 직접 생성한다.
  • 최초 지원 상위 유형은 돈 버는 방 · 스마트 금고 2개이며 향후 DIY를 확장한다.
  • 운영자도 동일 템플릿으로 공식 콘텐츠 성격의 컨트랙트를 생성할 수 있다. 코드 작성이 아니라 템플릿 선택과 파라미터 입력을 통한 인스턴스 생성이다.
  • 이용자 생성 컨트랙트의 온체인 조건은 관리자가 수정하지 않는다. 배포 후에는 오프체인 콘텐츠·노출 정보만 수정한다.
2.6

헥토코인

  • 헥토코인의 소유·위탁 운영 주체는 헥토파이낸셜이다.
  • 우리 어드민에서는 실제 지급·획득·사용·잔액 이력을 확인할 수 없는 것으로 본다.
  • 우리 서비스는 필요한 경우 헥토파이낸셜에 지급 요청만 전달한다. 본인확인이 완료된 회원만 지급 요청 대상이 될 수 있다.
  • 지급 대상 지갑·네트워크, API·파일 전달 방식, 실제 지급 결과 조회 방식은 미결이다.
  • 전달 완료는 실제 지급 완료를 의미하지 않는다.
3

1차 구축 원칙

3.1

기존 데이터·API 우선

  • 회원·지갑·컨트랙트 데이터는 기존 서비스 DB와 API를 사용한다.
  • 어드민만을 위한 별도 온체인 인덱서나 실시간 자금 모니터링 시스템을 만들지 않는다.
  • 저장된 컨트랙트 주소·Tx Hash가 있을 때만 탐색기 링크를 제공한다.
  • 어드민 전용 신규 데이터는 블랙리스트·공식 콘텐츠 초안·노출 상태·운영 이력으로 제한한다.
3.2

조회 중심·변경 최소화

  • 회원과 지갑 정보는 조회만 제공한다.
  • 공식 콘텐츠는 생성·배포 요청과 오프체인 노출 정보를 관리한다.
  • 이용자 생성 컨트랙트는 조회와 노출·숨김만 제공한다.
  • 헥토코인 자산 자체를 관리하지 않는다.

노출 원칙

  • UID를 기본 운영 식별값으로 사용한다.
  • CI·DI 원문은 조회·검색·다운로드·로그에 포함하지 않는다.
  • 이름·휴대폰번호·생년월일은 1차 어드민 필드로 만들지 않는다.
  • 이메일·소셜 식별정보·지갑 주소는 마스킹한다.
  • 지갑 주소 전체 열람 기능은 데이터정책팀 확인 필요 후 제공 여부를 결정한다. 허용 시 메뉴 권한과 개인정보 열람 권한을 모두 확인하고 열람 이력을 남긴다.
  • 이용자 생성 컨트랙트의 참여자 목록·주소·개별 자금 내역은 표시하지 않는다.
  • 회원 목록 전체 다운로드는 제공하지 않는다.

공통 상세 동작

동시성·멱등

  • 공식 콘텐츠 생성 요청은 콘텐츠 ID 기반 멱등키를 사용하고, 요청 중 버튼을 비활성화한다.
  • 블랙리스트는 UID당 활성 건 1개를 원칙으로 한다.
  • 상태 변경 전 현재 상태를 재검증하고, 충돌 시 최신 정보 재조회 안내를 표시한다.

1차 완료 기준

  1. UID로 회원을 검색하고 본인확인 상태를 확인할 수 있다.
  2. 회원 목록에서 6개 네트워크 지갑 생성 결과를 N/6으로 확인할 수 있다.
  3. 회원 상세에서 6개 네트워크별 지갑 생성 상태를 확인할 수 있다.
  4. 지갑·컨트랙트 주소가 제공되는 경우 기본 마스킹된다.
  5. 블랙리스트 제한 기능을 개별 선택해 저장 즉시 적용할 수 있다.
  6. 블랙리스트 종료일 자동 만료와 수동 해제가 동작한다.
  7. 블랙리스트 등록·수정·해제 사유와 변경 전후 값이 기록된다.
  8. 블랙리스트가 신규 컨트랙트 생성·참여 API에 실제 적용된다.
  9. 헥토코인 지급 요청 기능이 구현되는 경우 신규 요청에도 블랙리스트가 적용된다.
  10. 운영자가 최초 2개 템플릿으로 공식 콘텐츠 초안을 만들 수 있다.
  11. 공식 콘텐츠 생성 요청이 중복 없이 처리되고 배포 결과를 조회할 수 있다.
  12. 공식 콘텐츠는 배포 성공 후 기본 숨김이며 운영자가 별도로 노출할 수 있다.
  13. 이용자 생성 컨트랙트는 읽기 전용으로 조회되고 온체인 조건을 수정할 수 없다.
  14. 공식·이용자 컨트랙트의 노출·숨김과 처리 사유가 이력에 반영된다.
  15. 숨김 후에도 기존 참여자의 조회·청구·반환 경로가 유지된다.
  16. 목록에는 마스킹 개인정보만 표시되고 CI·DI 원문이 화면·로그에 포함되지 않는다.
  17. 개인키·MPC 키 조각·사용자 대신 서명·자산 이동·잔액 조정 기능이 존재하지 않는다.
